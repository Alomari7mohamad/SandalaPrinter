# Sandala Printer

تطبيق سطح مكتب عربي لإدارة المطبعة، مبني باستخدام Electron وReact وTypeScript وSQLite.

## تشغيل التطوير

```powershell
npm install
npm run dev
```

يشغّل الأمر خادم Vite ونافذة Electron مع Hot Reload.

## التحقق والبناء

```powershell
npm run typecheck
npm run test
npm run build
```

## إنشاء مثبت Windows

```powershell
npm run electron:build
```

الناتج المتوقع داخل `release` باسم `Sandala-Printer-Setup.exe`.

يجهّز البناء أيضًا ملفات التحديث الثلاثة في جذر المستودع: `latest.yml` و`Sandala-Printer-Setup.exe` و`Sandala-Printer-Setup.exe.blockmap`. ارفعها مع تغييرات الإصدار في دفعة واحدة إلى فرع النشر على GitHub Pages. عند تفعيل الفحص التلقائي، يتحقق التطبيق من قناة التحديث عند التشغيل ثم كل دقيقة.

## نشر تحديث بنفسك من التيرمينال

المتطلبات: Windows وNode.js وتبعيات المشروع، وGit، وGitHub CLI (`gh`) مسجّل الدخول بحساب يملك صلاحية الرفع إلى المستودع. عند الحاجة شغّل `gh auth login` بنفسك؛ لا تضع أي رموز وصول في ملفات المشروع.

1. احفظ تعديلات المصدر في Git بعملية commit كالمعتاد. يجب أن يكون فرع `main` غير متأخر عن GitHub وألا توجد ملفات معدّلة غير محفوظة. لا تضف قواعد البيانات أو ملفات أسرار إلى Git.
2. افتح PowerShell داخل المشروع ثم شغّل:

```powershell
cd "C:\Users\mo.w\Desktop\Sandala_Printer"
npm run release
```

الأمر يرفع الرقم تلقائيًا، مثل `1.0.1` ثم `1.0.2`، ويختبر المشروع ويبني المثبت ويجهّز ملفات التحديث، ثم يحفظ **ملفات الإصدار المحددة فقط** ويرفعها إلى GitHub. ينتظر نجاح Pages ويتحقق من بصمة المثبت وملف blockmap المنشورين. لا تحتاج لتعديل `latest.yml` أو رفع المثبت يدويًا. قد تظهر نوافذ اختبار قصيرة ببيانات مؤقتة منفصلة؛ لا تُستخدم بيانات البرنامج المثبّت ولا تُرسل طباعة فعلية.

لفحص الجاهزية فقط، دون تغيير رقم أو بناء أو نشر:

```powershell
npm run release:check
```

لإصدار أكبر أو رقم محدد أعلى من المحلي والمنشور:

```powershell
npm run release -- minor
npm run release -- major
npm run release -- 1.2.0
```

شغّل **أمرًا واحدًا مناسبًا فقط** لكل إصدار. `git push` وحده ينشر المصدر ولا يبني ملف التطبيق، وإعادة نشر الرقم نفسه لا تولّد إشعار تحديث. يلزم رقم أعلى من المثبّت، ثم الفحص التلقائي أو «فحص التحديثات» في الإعدادات.

### عند فشل النشر

- الأداة تتوقف عند الخطأ ولا تحذف تغييراتك ولا تخفّض رقمًا ولا تنفذ `force push`.
- إذا فشل الاختبار أو البناء بعد زيادة الرقم: أصلح السبب، واحفظ الإصلاح وملفي `package.json` و`package-lock.json` في commit **محلي**، ثم شغّل `npm run release -- --retry` لإعادة بناء الرقم الذي لم يُنشر بعد. لا ترفع ملف `latest.yml` وحده.
- إذا نجح الرفع لكن انقطع الانتظار أو التحقق: شغّل `npm run release -- --verify-only`. لا يرفع رقمًا ولا يعيد البناء أو الرفع.
- إذا كان الفرع متأخرًا أو رُفضت صلاحية الرفع، عالج رسالة Git أو تسجيل الدخول ثم أعد المحاولة؛ لا تستخدم `force`.

بيانات المبيعات والمنتجات منفصلة عن المثبت؛ هذه الأوامر لا تعيد تهيئة قاعدة بيانات التطبيق.

## تخزين البيانات

قاعدة SQLite تُنشأ تلقائيًا عند أول تشغيل داخل مجلد بيانات التطبيق الخاص بالمستخدم، مع WAL وForeign Keys. لا تُخزن قاعدة البيانات داخل مجلد التثبيت، لذلك تبقى بيانات المستخدم محفوظة عند تحديث البرنامج.

## حالة التنفيذ

- PHASE 1: Electron + React + Vite + TypeScript + SQLite + RTL + Layout + Navigation — مكتملة.
- PHASE 2: الخدمات والتصنيفات وقواعد الأسعار ومحرك التسعير وSeed Data واختباراته — مكتملة.
- PHASE 3: الطلب الجديد وحساباته والعملاء والمدفوعات — المرحلة التالية.

## بيانات PHASE 2

- 7 تصنيفات أساسية.
- 26 خدمة ومنتج أساسي.
- 84 قاعدة تسعير مؤكدة دون استنتاج أسعار للكميات غير المعرفة.
- Seed Data أساسي مستقل عن البيانات التجريبية، يُطبّق مرة واحدة ولا يستبدل تعديلات المستخدم.
- محرك التسعير موجود في `src/shared/pricing` ويستخدم Decimal للحسابات المالية.
- إدارة الخدمات والأسعار متاحة من الواجهة، وجميع العمليات تمر عبر IPC محدود إلى Main Process.
